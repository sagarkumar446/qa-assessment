# QA Assessment

This repository is used for QA assessment evaluation. All issues, bug reports, test cases, and QA-related artifacts will be tracked here.

**Repo Link:** https://github.com/sagarkumar446/qa-assessment

---

## Issue Format

Every issue should follow this structured format:

| Field | Description |
|-------|-------------|
| **Title** | Concise summary of the issue |
| **Precondition** | Conditions that must be true before the steps are performed |
| **Description** | Detailed description of the issue |
| **Steps to Reproduce** | Numbered steps to reproduce the issue |
| **Expected Result** | What should happen |
| **Actual Result** | What actually happens |
| **Severity** | Critical / High / Medium / Low |
| **Priority** | P1-Immediate / P2-CurrentSprint / P3-NextSprint / P4-Later |

## Labels

### Severity
- `Severity-Critical` - System crash / Data loss / Security vulnerability
- `Severity-High` - Major functionality broken / No workaround
- `Severity-Medium` - Functionality impaired but workaround exists
- `Severity-Low` - Minor / Cosmetic issue

### Priority
- `P1-Immediate` - Fix immediately
- `P2-CurrentSprint` - Fix in current sprint
- `P3-NextSprint` - Fix in next sprint
- `P4-Later` - Fix when time permits

### Type
- `bug` - Bug report
- `test-case` - Test case documentation
- `enhancement` - Improvement suggestion
- `question` - Clarification needed
